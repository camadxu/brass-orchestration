# Оркестровка и переложение для медных

Применять к брэсс-квинтету, ансамблю тромбонов, brass band, оркестровой меди, проверке и точечным правкам MusicXML/MuseScore, партиям и поиску источников. Это музыкальная оркестровка, не управление AI-агентами.

**Результат — проверяемая партитура, а не обещание хорошего звучания.** Не сдавать финал без отчёта о проверках и просмотра печатных материалов. Валидатор — ограниченный анализатор, не музыкальный судья: его PASS не доказывает качество, REJECT не разрешает автоматически переписывать музыку.

## When to Use

Использовать для музыкальной оркестровки меди, переложений, сверки источников и выпуска партий. Для распознавания скана сначала применять OMR-процесс, для общих операций PDF — профильный скилл. Не использовать для оркестрации программных агентов.

## 1. Установи задачу и источник

Перед изменением нот зафиксировать:
- создание / переложение / сверка / малая правка / только оформление;
- автор, произведение, редакция, конкретный мастер и SHA-256; номер версии результата;
- точный состав и число исполнителей, строй каждого инструмента, нотация written/concert, ключи; не считать название инструмента достаточной спецификацией;
- уровень и реальные возможности музыкантов, темп, границы тактов, что обязательно сохранить;
- формат сдачи: мастер, PDF партитуры, партии, отчёт; публикация не подразумевается.

Спросить только то, что меняет ноты или состав. Присланное не перезаписывать: исходник неизменяемый, работа в отдельном каталоге. Для MXL читать `META-INF/container.xml`, не предполагать имя `score.musicxml`; не делать слепой extractall недоверенного ZIP. При PDF/OMR помечать распознавание как черновик до сверки с изображением. Аудио — референс, не доказательство точной транскрипции.

## 3. Музыкальный цикл

1. Разобрать источник: форма и номера тактов, мелодия, контрапункт, бас, гармония, ритмический слой, динамическая траектория.
2. До нот составить карту «такты → функция → инструмент → регистр → передача/дыхание». Объяснить сокращения и изменения; не выдавать редакторское решение за авторскую ноту.
3. Сделать репрезентативный фрагмент, затем развить форму. `voice_quintet.py` годится для учебного аккордового квинтета; не навязывать его свободной фактуре, тромбонному ансамблю или цитате из источника.
4. Проверять по трём независимым направлениям: **соответствие источнику**, **исполнительская применимость**, **печать и комплектность**. Запустить применимые скрипты, разобрать каждое существенное замечание.
5. Исправить подтверждённые дефекты. Не исправлять осознанные унисоны, октавы, регистровые контрасты только ради нулевого счётчика.
6. Из единственного утверждённого мастера получить партии; проверить партитуру и каждую партию после последней правки. Полный gate — `references/validation-and-delivery.md`.

Для малой правки: сохранить стиль и вёрстку, уникальный якорь внутри нужной партии/такта, `count(old)==1`, после — XML parse, локальный и семантический diff. Не делать MusicXML round-trip родного MuseScore-мастера ради одного изменения: он может потерять вёрстку. Если текстовая замена неоднозначна — остановиться, а не угадывать.

| `scripts/validate_brass.py` | MusicXML: диапазоны и эвристики плотности/голосоведения, `--level amateur\|pro`, `--json`; rc=1 при hard errors. Ограничения — в справочнике приёмки |
| `scripts/voice_quintet.py` | Учебный аккордовый квинтет: `--prog 'Bb,Eb,F,Bb' --bars 2 --rests 3,6 --out score.musicxml` |

- `scores/CATALOG.md` — издание, состав и основание описания каждого файла. В каталоге есть немедные переложения, фрагменты и ZIP, а не только полные брэсс-партитуры.
- `docs/` — история; `_incoming/` — транспорт, не действующая опись.

Общий принцип искать у Римского-Корсакова, духовой оркестр у Анисимова, таблицы у Мальтера, дополнения у Блюма. Указывать автора, редакцию, PDF-страницу/печатную страницу; OCR использовать для поиска, ноты и таблицы сверять по изображению. Не приписывать источнику собственные выводы. Наличие на IMSLP/WIMA **не равно** public domain любого переложения.

## 6. Критические ограничения

- Written и sounding — разные высоты. Труба Bb обычно звучит на б.2 ниже, валторна F на ч.5 ниже. Brass-band нотация имеет октавные различия; не транспонировать все партии одинаково. См. `references/brief.md`.
- Таблицы регистра и «N тактов без вдоха» — ориентиры/эвристики, не физические законы. Учитывать секунды, темп, динамику, тесситуру и музыканта.
- Не менять ноты stopped horn автоматически на полутон: способ записи, строй инструмента и компенсацию уточнять по источнику/у валторниста.
- Проверять распознавание инструмента скриптом. Альтовый тромбон может попасть в теноровую таблицу, `<unpitched>` — дать «has no notes»; неизвестный инструмент не считать проверенным.
- Печатный темп, playback-tempo, `<words>`, динамика и артикуляция требуют отдельной сверки: питч-дифф их не доказывает.
- Для конкретной ошибки достаточно ясного первичного доказательства. Второй независимый источник нужен при неоднозначности; число сайтов само по себе не доказывает ноту.

## 7. Сдача и самопроверка

Отчёт: **статус → файлы/версия → что проверено → замечания и исключения → что не проверено**. Приводить команды, результат, партии/такты и основание; не наследовать чужие счётчики. «Механически проверено» не значит «музыкально одобрено»; MIDI помогает искать события, но не доказывает баланс живой меди.

Самотест валидатора: `--write-demo demo.musicxml`, затем `demo.musicxml --level amateur` — ожидаются 2 ошибки / 9 предупреждений / REJECT (rc=1 намеренный). Подробные команды и регрессионные тесты каталога — `references/environment.md`. Проверить синтаксис всех скриптов; созданный файл без реального запуска не считать работоспособным.
