# Библиотека и доказательность источников

## Разрешение путей

`ORCH_LIBRARY` задаёт корень; по умолчанию `Path.home()/Documents/orchestration-library`. Не переносить Windows-путь на удалённый хост. `books/manifest.json` — реестр основных книг: `original`, `extraction`, `pages_index` относительно `books/`. `catalog.json` хранит относительные пути от корня базы.

## Найти и использовать

1. Проверить корневой README и `library_catalog.py --root PATH --check`. Если опись расходится — назвать проблему, не обновлять хеши ради зелёного отчёта.
2. Выбрать автора/издание по предмету: Римский-Корсаков — общая фактура; Анисимов — духовой оркестр; Мальтер — таблицы; Блюм — дополнение. Различия источников сохранять, не смешивать в фиктивную единую норму.
3. Искать термин в соответствующем TXT. По `.pages.json` найти страницу; PDF-страницу и печатный номер не путать. Сверять по изображению все диапазоны, знаки, нотные образцы и таблицы, которые определяют решение.
4. Формулировать: «источник говорит…» с страницей; «применяю к этому составу так…» отдельно. Если виден лишь OCR — обозначить ограничение.
5. Для партитуры сначала `scores/CATALOG.md`, затем титул/состав и нужные страницы самого файла. Имя файла и имя каталога могут ошибаться; не считать фрагмент полной партитурой.

## Сетевой слой

Карточки и текстовые извлечения восстановлены из дампа. `manifest.json`/`checks.json` слоя описывают историческую загрузку; это не сегодняшняя проверка ссылок или наличие PDF. В локальном наборе нет PDF Белкина/MOLA и HTML-снимков. Исторический `text/` соответствует нынешнему `texts/`. Сначала прочитать README слоя; не давать несуществующую локальную ссылку как готовый файл. Adler — библиографическое описание, не текст книги.

## Обслуживание

- `--check` только читает: отсутствующие, изменённые, неучтённые файлы и контрольные суммы книг.
- `--write` намеренно принимает нынешнее дерево как новую опись. Перед ним сохранить старый catalog, понять каждое изменение; ручные метаданные сохраняются по пути. При переименовании вручную перенести метаданные со старого пути.
- `--render` строит `scores/CATALOG.md` из catalog. Не править сгенерированный Markdown вместо JSON.
- `catalog.json` и производный `scores/CATALOG.md` исключены из собственной хеш-описи, иначе возникнет циклическая зависимость. Остальные файлы, включая историю и транспорт, проверяются.
- SHA-256 доказывает неизменность байтов относительно описи, но не достоверность издания и не право публикации. Опись не криптографически подписана.

## Миграции

До переноса снять перечень путей/размеров/SHA-256 и проверить резервный ZIP. Сначала dry-run с проверкой отсутствия коллизий, затем перенос с журналом. Только пустые каталоги удалять. Если обновляешь документацию и одновременно обещаешь сохранить исходные хеши, сохранить исходные документы в `docs/history/originals/` — изменить байты и сохранить прежний хеш невозможно.

Не восстанавливать ZIP поверх нового дерева и не применять `git reset --hard` как универсальный откат: это оставит дубли либо уничтожит новые правки. Переместить текущее дерево в резерв, восстановить снимок в пустой каталог, сверить хеши, транспорт вернуть по журналу. Git — отдельный `revert` только своих коммитов после проверки рабочего дерева.

## Права

Сайт IMSLP/WIMA — происхождение, не лицензия всего файла. Произведение, редакция, современное переложение, набор и снимок могут иметь разные условия. Проверять конкретную лицензию и применимую юрисдикцию перед распространением. Личные копии не публиковать вместе со скиллом; в GitHub отправлять методику и код, не книги и сетевые тексты.
