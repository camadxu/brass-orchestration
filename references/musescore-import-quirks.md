# MuseScore 4: quirks импорта и полиграфия

Источник: bitwize-music-studio/claude-ai-music-skills, `sheet-music-publisher/musescore-reference.md`
(выжимка от 2026-11-15; их GUI-шорткаты и AnthemScore-пайплайн выброшены, оставлено то, что
применимо к headless-процессу этого скилла).

## Что ломается при импорте/генерации MusicXML

- **Неполные такты** — проверять отдельно длительности каждого голоса, backup/forward, аккорды, tuplets и затакты. `validate_brass.py` не доказывает полноту тактов; не приписывать ему такую проверку. Исправлять в рабочем мастере и сверять повторный импорт/рендер.
- **Группировка пауз** — босую целотактовую MuseScore печатает правильно (см. SKILL.md), но
  промежуточные (половина+четверть и т.п.) не перегруппировывает — группировать по долям в источнике.
- **Свинг vs триоли** — различать реально нотированные триоли и исполнительский swing. Сохранять конвенцию источника; не заменять одно другим автоматически.
- **Tie vs slur** — tie — звуковая связь одной высоты (через такт), slur — фразировка разных нот.
  В MusicXML `<tie>` и `<slur>` независимы; перепутанные дают фантомные легато при плейбеке.
- **Биминг** — по метру, группировке и стилю, не универсально «по четвертям». MuseScore при импорте может перекроить явные `<beam>` из файла —
  финальную группировку сверять по PNG-рендеру, не по XML.
- **Темп** — печатный `<metronome>` и `<sound tempo>` могут расходиться (см. SKILL.md); цитировать
  оба с ярлыками.
- **Ghost notes** — шум транскрипции становится нотами. Мы не транскрибируем, но при правке чужих
  MusicXML лишние ноты сверять против источника, не доверять файлу.

## Чек-лист полиграфии перед сдачей

Механика меди (диапазоны, воусинг, дыхание) — `validate_brass.py`. Печать — отдельно:
- [ ] ключевые знаки транспонирующих партий (Bb +2, F +1) — по PNG, не по XML
- [ ] размер и темп в первом такте; смена размера с репризой знака
- [ ] все такты полные; паузы сгруппированы по долям
- [ ] биминг по долям, лучи не через долю
- [ ] tie/slur не перепутаны
- [ ] динамика и изменения соответствуют источнику/плану, без искусственного минимума обозначений
- [ ] артикуляция (стаккато, акценты) по плану аранжировки
- [ ] page breaks на границах секций; поворот страницы не посреди фразы
- [ ] title/composer в score properties (без номеров треков), копирайт
- [ ] PNG каждой парты просмотрен глазами

## Два уровня качества

- **Минимально годно** (черновик на согласование): правильные ноты в основном, читаемая вёрстка,
  заголовок/автор, структура формы.
- **Publishing ready** (отдача игрокам): чистая гравировка, верные ключи/размеры, динамика и
  артикуляция, повороты страниц на естественных границах, кии и многотактовые паузы в партиях
  (см. `references/validation-and-delivery.md`).

## Troubleshooting импорта

- «не открывает XML» — проверить расширение, валидность XML и поддерживаемую структуру; не утверждать, что MuseScore читает только mscz/mscx 4.x. Конкретный старый формат проверять на копии. PDF — не редактируемый нотный вход этого конвейера.
- «плейбек не тот» — сверить `<sound tempo>` vs `<metronome>`; транспозицию `<transpose>` в партиях.
- «ноты не в том ключе» — у нас ключи партий проверяет валидатор; в чужих файлах различать clef и
  транспозицию инструмента (труба Bb пишется на б.2 выше звучания).
